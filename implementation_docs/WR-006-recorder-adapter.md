# WR-006: `gpu-screen-recorder` adapter

## Goal

Implement the single concrete boundary that translates retained capture settings and coordinator commands into the exact long-lived GSR replay-buffer lifecycle proven by WR-000/WR-002. GSR chooses and reports separate replay/regular artifacts; Recorder does not combine them.

## Dependencies

WR-002 and WR-003 must be `DONE`.

## Owned files

- `native/src/recorder.rs`
- `native/src/process.rs` containing only checked Unix signal/termination helpers reused by WR-007
- `native/src/lib.rs` module export
- `native/Cargo.toml`, `native/Cargo.lock`, `flatpak/cargo-sources.json` for the one approved dependency
- recorder tests in that module
- one small executable fixture under `tests/native/bin/` when needed to capture argv/signals/hook events

## Interface

Use one concrete `Recorder`; add a narrow test trait only if a generic coordinator parameter cannot substitute the fake. Do not create multiple backends.

```rust
pub struct StartRequest {
    pub id: RecordingId,
    pub requested_replay_ms: u64,
    pub mode: RecordingMode, // Automatic, Manual, or Test(category)
}

pub struct CaptureArtifacts {
    pub replay: Option<PathBuf>,
    pub regular: PathBuf,
    pub requested_replay_ms: u64,
    pub regular_started_at_ms: i64,
    pub regular_stopped_at_ms: i64,
}

impl Recorder {
    pub fn arm(&mut self, config: &CaptureConfig) -> Result<(), RecorderError>;
    pub fn begin(&mut self, request: StartRequest) -> Result<CaptureStarted, RecorderError>;
    pub fn end(&mut self, id: &RecordingId) -> Result<CaptureArtifacts, RecorderError>;
    pub fn cancel(&mut self, id: &RecordingId) -> Result<CaptureArtifacts, RecorderError>;
    pub fn reselect_target(&mut self, config: &CaptureConfig)
        -> Result<CaptureTargetSelection, RecorderError>;
    pub fn audio_devices(&mut self) -> Result<AudioDevices, RecorderError>;
    pub fn poll(&mut self, now_ms: i64) -> Vec<RecorderEvent>;
    pub fn shutdown(&mut self) -> Result<(), RecorderError>;
}
```

`CaptureStarted` records requested replay and the regular-start time. Actual usable replay/media start is known only after WR-007 trims/combines artifacts. Errors distinguish Busy, NotArmed, missing/invalid hook artifact, invalid settings/device, permission/selection denied, spawn/child failure with bounded log tail, and I/O.

## GSR process and hook contract

1. Build argv directly from `CaptureConfig` using `std::process::Command`; one function maps exact WR-000 flags/order, including separate `-o` replay and `-ro` regular directories plus `-sc` hook. Pass paths/devices as `OsString`, never a shell string.
2. Keep one long-lived replay-buffer child and at most one active recording ID. Illegal transitions return typed errors without changing the live session.
3. Write the minimal app-private hook script GSR requires. One shell `printf` appends timestamp, event kind, and GSR-produced path as one TSV record; Recorder writes the script with the literal events-file path embedded and never executes hook output. Exact argv per WR-000's recorded `-sc` contract; shape:

   ```sh
   #!/bin/sh
   # generated by Recorder; $1 = event kind, $2 = saved artifact path
   printf '%s\t%s\t%s\n' "$(date +%s%3N)" "$1" "$2" >> "/app-data-dir/gsr-events.tsv"
   ```

   ```text
   1755620000123	replay_saved	/…/replays/Replay_2026-07-19_20-13-20.mp4
   1755620180456	regular_saved	/…/recordings/Video_2026-07-19_20-16-00.mp4
   ```

   `arm` truncates the events file and resets a stored byte offset; `poll` reads only newly appended complete lines from that offset. Accept an event only when its kind matches the stage the single active recording is waiting for and the artifact's canonical parent is the configured replay/regular directory; ignore everything else with one bounded diagnostic. There is no persistent journal, sequence numbering, compaction, or restart recovery in Recorder.
4. `begin` rejects a second active recording, registers the replay-event wait, sends replay-save (`SIGUSR1` in the proven baseline), then toggles regular recording (`SIGRTMIN`). Automatic requested replay is detection delay plus lead-in already clamped by WR-008; manual/test use their recorded behavior. Do not wait for media or combine it here.
5. `end` toggles regular recording off, waits the recorded bounded time for the regular and any pending replay event, then returns the GSR-named paths/timestamps. Missing replay is allowed and becomes WR-007's regular-only fallback; missing regular is an error. `cancel` stops the same session and returns artifacts for coordinator/storage cleanup—it does not unlink paths itself.
6. Add `libc` because Rust `Child` cannot send required non-kill signals. Put one `process::send_signal(&Child, signal)` helper in `process.rs`; it rejects missing/PID 0, converts safely, calls `libc::kill`, and returns the OS error. Use libc's `SIGRTMIN()` value. WR-007 reuses this for FFmpeg termination. Do not add `nix`, shell out to `kill`, or build a supervisor abstraction.

Crash recovery is deliberately not Recorder's job. The current application has no restart recovery for interrupted recordings, so none is rebuilt here; interrupted-capture cleanup is WR-007's startup orphan sweep. Recorder holds no persistent state beyond the truncate-on-arm events file.

## Restart, target, diagnostics, shutdown

1. Preserve the current unexpected-exit policy: while `desired_running`, report and retry at 2, 4, 8, 16, then capped 30-second delays indefinitely, including repeated restart failures; reset attempts after a successful stable arm; stop only on disarm/shutdown or when coordinator deliberately replaces invalid configuration. Track deadlines in Recorder and advance through coordinator `poll`; no timer/retry thread/framework.
2. Capture-target selection/reselection uses WR-002's token contract. Return the new reusable token when available so coordinator atomically saves `capture_target_token`. Reselection invalidates the old token only at the proven safe point; cancellation preserves the prior usable target.
3. Audio discovery returns stable ID plus label for output/input selectors. No device cache/hotplug monitor.
4. Do not pipe child output to a reader thread. Open the current recorder log and pass cloned file descriptors as stdout/stderr. On child failure read at most its final 8 KiB for diagnostics.
5. Shutdown finishes/cancels active regular recording per WR-000, stops the replay child with the exact escalation timeout, cancels restart/event waits, and leaves no child.

## Acceptance criteria

- Argv matches WR-000 and paths/devices with spaces/non-ASCII remain single arguments.
- Hook correlation rejects duplicate, wrong-kind, and outside-directory paths; the events file is truncated on arm.
- Automatic/manual/test begin/end return the right GSR replay/regular artifacts and timestamps; missing replay is distinguished from missing regular.
- Busy/wrong-ID cannot affect the active session.
- Repeated capped restart/failure, success reset, disarm stop, reselect cancel/success, denial reporting, and shutdown match baseline.
- No shell command, async runtime, generic supervisor, OBS abstraction, extra reader thread, or alternate backend exists.
- `libc` is this ticket's only added direct dependency and Flatpak Cargo sources are regenerated.

## Tests and manual verification

Use the fake executable/event TSV for one argv table and focused lifecycle cases: replay+regular, outside/missing events, missing replay, busy/wrong ID, repeated restart schedule/reset/stop, reselection, and shutdown. Then repeat arm/save replay+regular/audio/reselect/shutdown with real GSR inside Flatpak and record both artifact paths/hashes. Do not mock OS process primitives beyond the fake executable/event file.

## Not in scope

Activity decisions/force-end outcome, FFmpeg trim/concat, storage finalization, UI, global hotkeys, device hotplug monitoring, or recovery states absent from the proven protocol.
